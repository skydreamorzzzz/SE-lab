# 拾物集 · 二手交易系统

六个主要页面直接基于 Lab 2 原始HTML/CSS/JavaScript迁移，保留布局、图标、卡片、筛选、弹窗及审核抽屉。普通账户现在可同时购买与出售。

Java 21 / Spring Boot 3.5 / Maven / Thymeleaf / JPA / H2 文件数据库。基于原实验一需求和实验二“拾物集”原型继续开发，所有开发在原 Git 仓库的 `main` 上进行。此文件是运行说明，不是实验报告。

## 启动与构建

```powershell
cd E:\lab3\implementation\lab3
.\mvn-local.ps1 test
.\mvn-local.ps1 package
.\run-local.ps1
```

支持 Windows PowerShell 5.1 与 PowerShell 7。`run-local.ps1` 含中文提示，须保留 UTF-8 BOM；密码使用兼容两者的安全输入。

访问 http://localhost:8080 。本机隔离安装的 JDK/Maven 位于 `E:\lab3\.tools`，启动脚本会使用它们。其他电脑配置 Java 21 和 Maven 后可直接执行 `mvn test`、`mvn package`、`java -jar target/marketplace-1.0.0.jar`。

普通买卖账户在页面注册。首次管理员启动时由脚本询问用户名与密码，不保存明文；已存在账户不会被覆盖。超级管理员是 ADMIN 角色的额外权限属性，可首次执行：

```powershell
.\run-local.ps1 -SetupSuperAdmin
```

也可在首次启动前通过 `MARKET_ADMIN_USER/PASSWORD` 或 `MARKET_SUPER_ADMIN_USER/PASSWORD` 环境变量提供凭据，启动后清除密码变量。没有默认密码。密码至少8个字符、包含大小写/数字/特殊字符，UTF-8编码不超过72字节。

数据库在 `data/market.mv.db`，上传媒体在 `data/media`；重启仍保留。脚本始终使用项目目录作为运行目录。无需重建数据库；MigrationTest 验证原 MVP 账号和商品可升级并继续交易。

## 功能与验收入口

1. 卖家：发布闲置 → 保存草稿 → 商品管理调整库存 → 提交审核。草稿允许未填完整；分类格式为 `数码电子/相机`。主图可填 `/images/sample.svg`，也可在媒体上传页上传后复制地址。支持附图、一个视频及品牌/型号/年限/产地/客服/发货信息。
2. 管理员：审核后台通过或填写原因驳回。普通管理员不能修改商品正文，也不能设置抽成、促销或管理其他管理员。超级管理员在平台规则页管理上述事项、启停普通管理员和下载备份。
3. 买家：个人中心填写收货地址 → 搜索/筛选/排序 → 立即购买或加入购物车并分组 → 下单 → 模拟支付；卖家发货，买家模拟物流签收或主动确认收货。双方独立评价，商品页和卖家页展示信誉。
4. 预约：售罄商品申请；重复申请合并到同一有效队列记录，合计不得超过计划；取消后新预约重新排队。卖家补货按FIFO部分分配库存，在预约页确认已分配部分并生成待支付订单。
5. 议价：卖家勾选支持议价并审核通过；买家报区间内价格，卖家接受后锁价/库存15分钟。买家在“我的议价记录”转订单，不重复扣库存；失效/下架/关键字段改变均拦截旧报价。
6. 售后：订单“售后申请与结算”入口。未发货直接退款；已发货及已收货需要退货。卖家同意后买家填写退货物流，卖家确认收货才退款并恢复库存；已结算订单退货退款会冲正原结算并保留记录。拒绝后恢复原履约状态。48小时未处理自动同意，退货仍须实际走完模拟退回流程。
7. 社区：商品收藏、关注卖家、单向屏蔽、浏览/搜索历史在个人中心管理。屏蔽仅影响当前用户，不通知卖家，不删历史订单。购物车打开时重新核验失效原因，关键操作仍由服务端校验。
8. 治理：举报/申诉页提交商品或账户编号及原因，可上传图片。同一人同一对象每上海自然日最多一次。举报不自动下架，管理员单独处置并反馈；商品申诉通过回到待审核，不能直接上架。封禁保留订单，已登录会话也受限制，可继续申诉。
9. 榜单与统计：首页底部进入全站/分类日周月成交榜。管理员统计仅返回聚合数据，1–4笔样本合并并隐去金额/件数；普通管理员无法查看他人的单笔订单、手机号或地址。
10. 账户验证：身份验证页生成一次性恢复凭证，离线保存；登录页可使用凭证重设密码。绑定手机号先验证当前密码，再核对5分钟验证码，最多5次尝试。

15分钟支付/议价超时、48小时退款超时和签收7天自动收货由30秒周期任务处理；无物流签收不会自动收货。所有金额、库存、角色和状态在 Service 层最终校验，核心事务使用商品→订单锁顺序。

## 模拟边界与设计口径

- 支付、物流、退款与卖家结算均为本地模拟，无真实资金和运营商接口。
- 手机验证码明确展示为“本地短信模拟”，用于课程流程验证，不声称完成真实手机所有权验证。
- 找回密码使用预先保存的一次性高熵恢复凭证，避免依赖外部短信服务。凭证只显示一次、数据库仅保存哈希。
- 直接购买按公开最低价减平台促销比例成交；议价按区间内协商价成交，不再叠加平台促销；结算按确认收货时的抽成比例保存费用快照。
- 新旧程度排序采用全新/近全新/数字成色映射；卖家信誉排序基于收到的真实订单评分。日榜按当日0点、周榜按周一、月榜按月初，均使用上海时区。
- 平台规则和超级管理员管理为课程范围，不提供真实支付清算、外部物流或短信接入。

## 测试与证据

`mvn test` 同时执行 Checkstyle、业务/权限/并发/迁移/备份和真实性能测试。PerformanceTest 在独立 H2 文件库中构造1万件商品，10个真实HTTP登录会话，每项列表/搜索/下单/支付各100次采样；先预热20次浏览请求，P95分别检查300/300/1000/1000毫秒，异常请求直接使测试失败。结果写入 `target/performance-results.json`，性能受本机负载影响。

Chrome 端到端验证：

```powershell
npm install --prefix target/browser playwright
$env:PLAYWRIGHT_MODULE = "$PWD/target/browser/node_modules/playwright"
node scripts/browser-smoke.cjs
```

需 Chrome（可设置 `CHROME_PATH`）及 Java 21（可设置 `JAVA_HOME`）。脚本在18080端口启动独立文件数据库，使用随机验收账号，检查六个实际页面、完整交易、预约、退款、治理、上传和重启恢复；结果及截图位于 `target/design-validation/<运行编号>`。`browser-smoke.cjs` 现在调用同一套设计验收脚本。备份、数据库、恢复凭据与日志只保留于被忽略的 target。仓库 `evidence/design/` 仅保留已挑选的参考/实际截图、聚合测试结果及原文件哈希。

原HTML默认位于本工作目录的实验二交付路径；可通过 `LAB2_UI_PATH` 指定其他UI界面目录。原文件缺失时浏览器脚本会明确记录跳过视觉比较，仍执行业务流程；本轮验收已实际使用全部六份原HTML进行比较。源码与原样式核对：

```powershell
python scripts/check-design-assets.py
```

迁移对应、主要调整及实际验证记录见 [docs/LAB2-ALIGNMENT.md](docs/LAB2-ALIGNMENT.md)。

启动脚本回归：`node scripts/test-launcher.cjs` 会使用 Windows PowerShell 5.1，在隔离数据库上验证普通管理员与超级管理员的安全密码输入、实际启动和登录。设置 `POWERSHELL7_PATH` 可追加 PowerShell 7 场景；不修改系统执行策略。

源码统计：`python scripts/count-source.py`，按非空、非注释Java物理行统计，保留字符串中的URL，包含大括号；分别列主代码与测试，不计HTML/CSS/JS及构建产物。

## 备份恢复

超级管理员平台页下载的ZIP包含 `database.zip`（H2在线一致性快照）和 `media/`。恢复时先停止应用，在独立目录解压验证，备份好现有 data 后，将内层ZIP中的数据库文件与media恢复到新的运行目录，使用对应 `spring.datasource.url` 启动。不要在应用运行时覆盖数据库。PerformanceTest 已实际从备份恢复到独立H2数据库并查询验证账号，同时检查媒体包含在备份中。

- `src/main/java/edu/market`：实体、Repository、Service、Controller与安全/定时任务；类名体现职责，依赖为Controller→Service→Repository。

- `REQUIREMENTS-COVERAGE.md`：34项需求对应实现、验证和模拟边界。
